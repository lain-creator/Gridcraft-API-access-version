# 中英文界面对齐修复 · 2026-10-27

对应 Mac 补丁版本：`0.12.1-api.20261027.1`。

## 问题和修复

- `egui 0.36.2` 的按钮内部布局继承父布局，导致竖排翻译按钮靠左、右侧标题按钮靠右。
  本地 `vendor/egui` 补丁将按钮内容默认设为双轴居中，菜单内用 grow atom 分隔的名称与快捷键仍各居一侧。
- 单行输入框默认顶部对齐，控件变高时文字和光标仍贴上边。仅单行输入改为垂直居中；
  多行问答、代码和公式输入不强制居中，以保留逐行阅读和编辑。
- macOS Hiragino 等 CJK 回退字体的上下度量不对称，使中文可见字形偏上甚至超出行框。
  使用字体真实字形包围盒及 ascent/descent/leading 计算 em 级修正，随字号和屏幕缩放生效，
  不依赖固定的像素偏移，也不改文字宽度、行高或单元格的原有格式。

## 验证入口

`cargo test -p gridcraft-ui-egui --test chrome_alignment` 覆盖：

- 100%、125%、150%、200% 缩放下，竖排、左到右、右到左布局中的中英文按钮居中和无裁切；
- 11、12.5、13、18 号普通/粗体中英文可见字形中心；
- 单行文字与光标的对齐，多行输入保持顶部对齐；
- 菜单名称和快捷键不重叠、仍分别靠左/右。

离线截图：`cargo run -p gridcraft-ui-egui --example chrome_alignment -- out.png [--settings] [--dark]`。
此示例只使用合成数据与不会联网的占位服务；不读取文档、API Key 或用户配置。

不会改写原工作簿，不会将所有数据单元格强制水平居中，不会发送任何数据到第三方 API。
Windows 共享同一源码修复；真实 Windows 字体及桌面显示仍需另行验证。
